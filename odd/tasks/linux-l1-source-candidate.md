## Findings
- F1 (CONFIRMED, cause: missing `lsof`; see the end of this finding). Original observation: after tray Quit, the private `engram serve` (pid 809443, port 7438, `ENGRAM_DATA_DIR=<tmp>/home/.engram`) stayed alive, reparented to `systemd --user`. Four Quit/relaunch cycles left exactly one such process (none per cycle). Each relaunch logged `cannot verify private memory listener on port 7438 (failed lookup); will not stop it`. Whether a relaunch reuses it is unverified. The user's real Engram (pid 10658, port 7437) was never touched.
  Probable cause (read in code, NOT confirmed by a run): `privateMemory()` (`packages/daemon/src/isolation.ts:283`) only returns a `stop()` after confirming the private port is empty, and it looks up the listener with `lsof` (`listeningPid`, ~line 409). This machine has no `lsof` (`command -v lsof` empty, `pacman -Q lsof` not found), so every launch logged `failed lookup; will not stop it` (first one at 19:38 local, before the orphan existed) and Quit had nothing to stop. `packaging/arch/PKGBUILD:11` depends only on `gtk3`, `webkit2gtk-4.1`, `libayatana-appindicator`; repo smoke scripts and tests do use `lsof`. Not checked: what `setup-arch.sh` installs, who spawned the Engram (daemon or engine), and the default `shared` mode. To confirm: install `lsof`, stop only pid 809443 (human OK), launch, Quit, expect `stopped the private memory server` in the log and 7438 free.
  Confirmation (session 5, A): after the human installed `lsof` 4.99.7 and the orphan was stopped (SIGTERM to pid 809443 only, after checking its `ENGRAM_DATA_DIR` was the temp dir), the launch logged no `failed lookup`. The daemon started a new private Engram (pid 1094735, parent a `pi` process, data dir in the temp dir). Tray Quit then logged `stopped the private memory server (pid 1094735)`; port 7438 and every Gentle Dot process were gone afterwards; the real Engram (pid 10658, port 7437) was untouched. Defect class: `lsof` is a runtime need on Linux that `packaging/arch/PKGBUILD`, the `SYSTEM_PACKAGES` list of `scripts/linux/setup-arch.sh` and the guide do not declare; without it, `GENTLE_DOT_ENGRAM=private` leaves the Engram running after Quit. Not tested: default `shared` mode, a `.deb`/Debian-Ubuntu machine, a fix. Unrelated: an `engram serve` with no data dir (pid 1213118) belongs to another `pi` session and was not investigated.
