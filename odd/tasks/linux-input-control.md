# Linux computer control — phase 2: input

## Specs
S1. Cinlo (2026-11-08): "es que esto es para el repo en general, para la gente, entonces la idea es q pueda hacer todo. asi como lo hace en windows o mac" — Linux reaches feature parity with the macOS and Windows computer control: the assistant sees the screen (done, phase 1) and operates it (input), through the same `mcp.rs` tool surface and permission/session model.
S2. Input on Hyprland/wlroots compositors goes through the session's Wayland protocols: `zwlr_virtual_pointer_v1` for pointer (absolute motion in capture-pixel coordinates, buttons, scroll) and `zwp_virtual_keyboard_v1` for keyboard (keymap XKB + keycodes). No privileged daemons (ydotool route was rejected: needs a privileged daemon).
S3. GNOME/KDE parity uses the RemoteDesktop portal instead; out of this phase, recorded as future work. Portability note goes in docs.
S4. Every input method keeps the shared safety model: working rings/overlay, session grant, panic shortcut, blocklist, and the risk check (`risk.rs`, `working.rs`, `mcp.rs` are shared and must not regress on other platforms).
S5. Tests: the shared event planner (`winput.rs`) and `InputEvent`/`KeyCombo` (`keys.rs`) are already cross-platform; Linux implements the emitter behind the existing `Desktop::post`/`post_typed` contract, tested against a fake connection where possible, and manually on Cinlo's Hyprland.
