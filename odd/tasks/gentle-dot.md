# Gentle Dot — always-on desktop and web assistant backed by Gentle Shell

Objective: a local, always-available assistant (floating Dot on macOS, menu bar, global shortcut, and browser) whose hidden engine is Gentle Shell with Engram. Design: `docs/design.md`.
Branch: `feat/gentle-dot` · Delivery strategy: `single-pr` (user choice, L7; forecast ~3,500 authored lines, recorded as a size exception) · Test runner: Vitest (`pnpm test`), Playwright (`pnpm e2e`), `cargo test` for `apps/desktop`.

## Specs

"Vamos a empezar con Mac, al principio."
  - Acceptance: a Tauri 2 macOS app shows a floating, always-on-top, draggable Dot (design §6). It also has a menu bar item with the menu listed in §6 and a global shortcut (default `⌥ Space`) that expands and collapses the panel. The Dot position persists across restarts.
  - Checks: `cargo test` for config and position persistence; a manual macOS checklist (T9) with observed results.

- **S3 — Gentle Shell runs behind it, unchanged.** User: "la idea es que por detrás corra GentlyAI, ¿bien? Gentle Shell, en este caso." "el agente va a hacer todo como lo hace Gentle Shell, literalmente. Todo lo mismo, usando Engram, usando todo."

- **S4 — The user does not know it is Gentle Shell.** User: "pero que el usuario no lo sepa."

  - Checks: unit tests for the sanitizer over recorded real events; one `@real-agent` test that asserts the identity answer contains "Gentle Dot" and none of the hidden names.
  - Assumption: the `gentle-shell` launcher forwards `--append-system-prompt` to Pi. T4 verifies it first; if it does not, T4 stops with **Needs your decision**.
- **S5 — Resume after a cut.** User: "Lo que tú decías de que si se corta, después no puede volver, con Engram sí es que se puede volver. porque la gente lo primero que va a hacer es ir a consultar a Engram para continuar. o si no tiene los datos de la misma sesión donde él existe."

- **S24 — Computer control (last item).** User (L43): "un item mas al final de todo, que haga como codex y que permitas controlar tu computadora, que pueda manejar tus aplicaciones y tal".
  - Acceptance (original draft, refined below in L60): the assistant can see the screen and operate apps (screenshots, mouse, keyboard, opening and switching apps) after the user grants macOS Accessibility and Screen Recording permissions, with an in-app guide for granting them. Safety: a visible "in control" state on the rose, a global panic shortcut that stops control instantly, approval per control session plus mandatory confirmation for risky actions (send, pay, delete, submit), an optional allowlist of apps, and a clear note when the selected model cannot use images. Likely delivered as a built-in MCP connector behind the S18 approval guard. Scope (L59): macOS only for now (user: "lo de controlar la computadora por ahora solo para mac"); Linux is out of scope.
  - **S24.1 Helper location.** A native helper inside the Tauri app (Rust, `apps/desktop/src-tauri`), never in the daemon or the engine, so macOS attributes Accessibility and Screen Recording to Gentle Dot.app and every rule below lives outside the agent's reach. It serves MCP (JSON-RPC 2.0 over streamable HTTP, `initialize`, `tools/list`, `tools/call`) on `127.0.0.1:<random port>/mcp`, requiring `Authorization: Bearer <token>` with a fresh random token per app launch. Off macOS the helper does not start.
  - **S24.2 Tools.** `screenshot {}`, `click {x, y, button?: "left"|"right", count?: 1|2|3}`, `move {x, y}`, `drag {fromX, fromY, toX, toY}`, `scroll {x, y, dx, dy}`, `type {text}`, `key {combo}` (for example `cmd+shift+t`, `return`), `open_app {name}` (name or bundle id), `list_apps {}`, `wait {ms ≤ 5000}`. Every action accepts an optional `intent` string. Coordinates are pixels of the latest screenshot; the helper maps them to logical points with the scale and origin of that screenshot. Screenshots of the display under the pointer are downscaled to a long edge of at most 1280 px (Anthropic: "pre downscale your screenshots before sending them to the API"; Pi resizes above 2000×2000), returned as an MCP `image` block (PNG or JPEG) plus a text block with `{imageWidth, imageHeight, scale, frontApp}`. Actions return a fresh screenshot. Gentle Dot's own windows are excluded from screenshots.
  - **S24.3 Session grant.** Any tool call (screenshots included) without an active session shows a native dialog owned by the app: "Allow Gentle Dot to see and control this Mac for 30 minutes?" (Allow / Deny). Deny returns a tool error and starts nothing. A session ends on timeout (30 min), the Stop button, the tray item "Stop computer control", or the panic shortcut **⌥⇧Esc**; ending drops queued actions immediately, and the next call asks again.
  - **S24.4 Guards enforced by the helper.** A fixed blocklist: no action targets Gentle Dot's own windows, System Settings, SecurityAgent, loginwindow, Keychain Access, or known password managers (1Password, Bitwarden, Dashlane, LastPass, Apple Passwords); a target is the frontmost app for keyboard actions and the app owning the window under the point for pointer actions. A rate limit of 10 actions per second. Risky actions need a native per-action confirmation showing the action and target: a click on an Accessibility element whose role is a button or menu item and whose title or description matches send, pay, buy, purchase, delete, remove, submit, confirm, transfer, place order, checkout, or their Spanish equivalents (enviar, pagar, comprar, eliminar, borrar, confirmar, transferir); `return` or `cmd+return` while the focused element is a default button or a send-like field; or any declared `intent` matching those words. The intent only adds checks, never removes them.
  - **S24.5 Permissions guide.** The app reports Accessibility (`AXIsProcessTrusted`) and Screen Recording (`CGPreflightScreenCaptureAccess`) status, can prompt for them, and deep-links to the System Settings panes. The connectors screen shows a built-in "Computer" entry with both statuses, grant buttons, a note that ad-hoc signed debug builds lose the grant on every rebuild (macOS ties it to the code signature), and a note when the current model does not accept images.
  - **S24.6 Visible state.** While a session is active, the rose shows an "in control" state, and the panel shows a banner with the remaining time and a Stop button.
  - **S24.8 Speed (L66, user: "anda muy bien pero lento, bastante lento"; "hagamos todas si").** (a) A `batch {steps: [{tool, ...args}], intent?}` tool runs up to 20 steps of the action tools (click, move, drag, scroll, type, key, open_app, wait) in one call and returns one screenshot at the end; every step goes through the same checks as a single call (session, epoch/panic, rate limit, blocklist, risky confirmation, coordinate mapping against the screenshot taken before the batch); the batch stops at the first refused, declined, or failed step and reports which steps ran. The tool descriptions steer the model to batch predictable sequences. (b) The helper gets faster: dependencies that encode and resize images are optimized in debug builds, and the settle wait after an action drops from 300 ms to about 150 ms (open_app keeps its longer wait). (c) Screenshots get lighter (lower JPEG quality) without losing legibility of UI text. (d) Explain and fix the 18 s `type` seen in L66 if it is the helper's doing.
  - **S24.9 Yolo mode (L67, user: "y mete un modo yolo").** User choices: "Solo las confirmaciones (recomendado)" and "Interruptor, se apaga solo (recomendado)". While on, risky actions (S24.4) run without the per-action confirmation; the session grant, the blocklist, the rate limit, the panic shortcut, and Stop stay as they are. A switch in Connectors → Computer and a tray item turn it on and off; turning it on asks a native confirmation owned by the app; it turns itself off when the app quits, after 1 hour, or on the panic shortcut (L74; Stop leaves it on), never persists to disk, and only the app (Tauri command or tray) can change it, never the engine or the WS. The rose and the session banner show when it is on.
  - **S24.7 Wiring.** The desktop webview asks the app for the endpoint and registers it with the daemon (`computer_register {url, token}`); the daemon renders a built-in `computer` MCP server into the engine's `mcp.json` (direct exposure, no in-engine approval cards, since the helper enforces) and removes it on `computer_unregister` or when that client disconnects. The web UI (VPS) never offers computer control.

- **S25 — Connector enforcement outside the agent's reach (stage 2, before publishing to other users).** Decided in L48. The daemon proxies MCP traffic: connector tokens live in the OS secure store (macOS Keychain, with an equivalent on Linux and the VPS), the engine sees only local proxy URLs, and enabled state, mode, and approvals are enforced by the daemon, not by files or an in-engine hook. Subagent child processes are covered too. Approvals must reach the user through a channel the agent cannot reach (L49: with the daemon access key, the agent could connect to the WebSocket and answer its own approval cards), for example a native OS dialog shown by the desktop app, or a per-window key never stored in a file the agent can read.
