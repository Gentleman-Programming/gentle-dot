# Wake word "oye dot" (voz que arranca la nota) con corte automático

Branch: `feat/wake-word-oye-dot`; baseline: `df52f3f` (`origin/main`, PR #103); isolated worktree: `../gentle-dot-wakeword`; the original checkout (`feat/mic-selector-r2`, PR #107) is not touched.
Delivery: single commit on the feature branch, local only, no push, no PR, no force-push. Engine: rustpotter 3.0.2 (Apache-2.0) over the existing AVAudioEngine stream. Evidence for the operating point: leave-one-out over 4 samples, margin 0.062, único umbral usable 0.45 (`~/Documents/personal/gentle-dot-wakeword-lab/loo.py`).

## Specs

- S1 — "detector detras de un flag APAGADO por defecto, activable desde Ajustes -> Voz". The detector never runs unless the user turns it on in Settings → Voice. The flag lives with the desktop config (`~/.gentle-dot/config.json`), is read at startup and applied live, and enabling it without the model present fails with a reason instead of silently doing nothing.
- S2 — "el audio del detector debe venir del MISMO AVAudioEngine del app (voice/macos.rs), NO de cpal ni de un proceso aparte: en esta maquina ese camino entrega silencio (-55 dB) y ademas duplicaria el micro". The detector consumes the 16 kHz mono PCM that `voice/macos.rs` already produces in its tap. No `cpal`, no second engine, no helper process, never two input streams open at once.
- S3 — "al detectar la frase, dispara el mismo camino de nota de voz que ya existe (no inventes otro)". A detection starts the existing recording path (`Voice::start` + the `voice://*` events the panel already consumes). No parallel recorder, no second transcript pipeline.
- S4 — "El .rpw va al data dir como planeaste, Y ademas agrega '*.rpw' al .gitignore del repo como red de seguridad (es una firma de voz)". The reference loads from `<data_dir>/wake-word/oye-dot.rpw`; it is never bundled in the build and never committed. `*.rpw` is ignored repository-wide.
- S5 — "loguea cada deteccion y cada fallo para que el uso real junte el dato que falta". Every detection (score) and every detector failure is appended as one JSON line to `<data_dir>/wake-word.log`. No dependency: the file is opened, appended and flushed per line.
- S6 — "Corte de la nota: el usuario quiere automatico. Implementa deteccion de silencio por energia sobre el MISMO stream del AVAudioEngine: corta tras ~1,5 s de silencio, con minimo de 1 s de nota y tope duro de 60 s; sin palabra de cierre." Energy-based silence detection over the same stream: stop after ~1.5 s of silence, never before 1 s of speech, hard cap 60 s, no closing word. The auto-stop only applies to recordings the wake word started; the panel's own button keeps its current behavior.
- S7 — "integrar el wake word en Gentle Dot con lo que hay (4 muestras, umbral 0,45, -m 5)". Operating point fixed by measurement: threshold 0.45, min_scores 5, the model built from the 4 existing samples.
- S8 — "Rama nueva desde main (no toques feat/mic-selector ni el PR #107), un commit, doc ODD propio" and "Nada de force-push". One commit on `feat/wake-word-oye-dot`, built from `origin/main`, with this document, the code, the tests and the design notes in it.

Two tests cover it: a noisy note ends, and noise after speech lets the silence run.
