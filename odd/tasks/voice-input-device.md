# Input device selection for voice
Branch: `feat/voice-input-device`; baseline: `e3c35e5` (after `feat/voice-push-to-talk`); delivery: work-unit commits on the feature branch, local only; no push or PR without an explicit decision.

## Specs
- S1 — "otra cosa que falta es un selector de microfono en las configuraciones". Settings offers the input devices by name, with the one in use, and changing it takes effect on the next recording without a restart.
- S2 — "config.json" (confirmed). The choice persists as `voiceInput` (`{ uid, name }`) in `config.json` and is applied when recording starts; Rust owns it, the panel only reads and writes it.
- S3 — "fallback al default con aviso" (confirmed). When the chosen device is gone, recording uses the system default input and the panel says so; it never records the wrong device silently and never blocks the note.
- S4 — "identidad por UID de CoreAudio" (confirmed). The stored identity is the device UID, never the name; the name is stored for display only.
- S5 — Hot audio configuration changes: a device change that stops the engine ends the recording with a message naming what happened ("the microphone X was disconnected"), never an empty transcript and never a silent death.
- S6 — Bug to reproduce before fixing: "con un microfono EXTERNO conectado, no se puede enviar ninguna nota de voz". The open path reports which device and which format it opened, so the reproduction yields evidence instead of a guess. The fix follows the evidence; it is not pre-decided.
- S7 — Out of scope: the OpenAI/webview path (`getUserMedia`) is dead in this install (`voice.transcribe: false`); Parakeet inherits the same PCM and needs nothing; Linux `pipe.rs` keeps the system default and is reported as a limit.
