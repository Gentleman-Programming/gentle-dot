## Activation Contract

Use for Gentle Dot packaging, runtime replacement, component provenance or release documentation.

## Hard Rules

- Keep Dot app/UI/daemon/native ownership and its private runtime separate from global tools.
- Consume a compatible Shell/Pi recipe and lock; reference canonical Gentle AI contracts without copying authority prompts.
- Keep Engram data outside binary replacement. Do not infer migration or publication permission.
- Verify full provider payloads; readiness never grants session permission. Preserve hands-owned indicators and effective Stop.
- Distinguish source, static, fake-transport, native-runtime and installed proof. Never report a failed attempt as successful.

## Decision Gates

| Condition | Action |
| --- | --- |
| Missing target, lock or provenance | Report the gap before activation. |
| Unpublished Dot hands | Retain local identity; never invent a URL or substitute blue upstream hands. |
| Documentation-only scope | Do not install, update, migrate or execute providers. |

## Execution Steps

1. Read the canonical contract and local checklist below; reconcile their source links with the checkout.
2. Identify owner, target and exact compatible tuple; record recipe, lock, hashes and licenses.
3. Plan binary replacement and rollback separately from data migration.
4. Run only applicable authorized checks; preserve failures and state missing proof.

## Output Contract

Return ownership, target/versions, changed paths, evidence boundary, failed/skipped/pending checks and the next gate. Label implemented, verified, planned and claimed states explicitly.
